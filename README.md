# codex-skill-over-mcp

Экспортёр MCP-ресурсов skill:// в файловые скиллы Codex. Он реализует тот же
[контракт](https://github.com/SpamX-dev/dsh-skills-over-mcp-plugin/blob/main/CONTRACT.md), что и провайдер dsh-skill-mcp, через
отдельное кратковременное соединение с сервером.

Codex загружает локальные скиллы из
[.agents/skills](https://learn.chatgpt.com/docs/build-skills). Поэтому адаптер
создаёт там управляемые копии SKILL.md. Подключения инструментов MCP настраиваются
отдельно: экспортёр не редактирует config.toml.

## Запуск

Node.js 22 или новее:

~~~powershell
npm ci
node src/cli.mjs --config examples/servers.json --destination D:/path/to/project/.agents/skills
~~~

Пример examples/servers.json рассчитан на расположение пакетов рядом в
этом рабочем каталоге. Перед запуском установите зависимости
module-architecture-mcp. Для другого проекта задайте его путь в аргументе
--root сервера и в проектном MCP-подключении Codex.

Конфигурация:

~~~json
{
  "servers": [
    {
      "name": "module-architecture",
      "command": "node",
      "args": [
        "D:/projects/dsh.plugins/module-architecture-mcp/src/server.mjs",
        "--root",
        "D:/path/to/project"
      ]
    }
  ]
}
~~~

cwd каждого сервера разрешается относительно файла конфигурации. Если cwd
не указан, используется каталог этого файла. destination разрешается
относительно рабочего каталога, из которого запущен экспортёр.

Поддерживаются необязательные args, cwd и env. Не храните секреты env в
публичном репозитории. Параметры команд и окружение не записываются в маркеры
экспортированных скиллов.

## Проверка и обновление

~~~powershell
node src/cli.mjs --config examples/servers.json --destination D:/path/to/project/.agents/skills --check
node src/cli.mjs --config examples/servers.json --destination D:/path/to/project/.agents/skills --server module-architecture
~~~

--check ничего не создаёт и не изменяет. Код возврата:

- 0: экспорт выполнен либо проверяемые копии актуальны.
- 1: в режиме --check есть отсутствующие или устаревшие копии.
- 2: конфигурация, сервер, ресурс или назначение не позволяют завершить операцию.

После изменения скилла на сервере повторите экспорт. Источник инструкций —
SKILL.md сервера; экспортированные файлы не следует редактировать вручную.

## Контракт записи

Экспортёр:

- читает все страницы resources/list и все skill:// ресурсы до начала записи;
- проверяет совпадение URI и frontmatter, имена и наличие описания и тела;
- сохраняет точные байты текста ресурса без переименования скилла;
- останавливается при коллизии имён между серверами;
- пишет происхождение и SHA-256 в .skill-over-mcp.json рядом с SKILL.md;
- отказывается перезаписывать чужие каталоги, ссылки и локально изменённые файлы;
- публикует обновление каждого скилла заменой каталога с восстановлением
  прежнего при ошибке переименования.

Ошибка удалённого чтения или предварительной проверки не применяет частичный
каталог. Ошибка файловой записи после начала публикации может оставить уже
обновлённые независимые скиллы; повторный запуск безопасно продолжит работу.

## Границы первой версии

Поддерживаются stdio-серверы и самодостаточные SKILL.md. Относительные ссылки на
scripts, references и assets отдельно не экспортируются. Удалённый HTTP,
фоновые подписки, автоматическое удаление исчезнувших ресурсов и изменение
конфигурации Codex не входят в этот адаптер.

Ограниченные политики вызова disable-model-invocation: true и
user-invocable: false отклоняются: экспортёр не делает вид, что семантика
dsh точно совпадает с настройками Codex. Скиллы с обычной политикой вызова
работают без преобразования.

## Проверка

~~~powershell
npm test
~~~

Тесты используют настоящий MCP-клиент и локальную фикстуру: проверяют пагинацию,
обновления, режим --check, сохранность локальных правок и отказ без записи,
если один из серверов недоступен или имена скиллов совпали.
